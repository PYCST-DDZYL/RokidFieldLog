## 第一阶段只验证两条独立路径

1. 眼镜：启动 FieldLog → 申请摄像头权限 → 点击触控板拍摄一张照片 → 私有目录持久保存 → 短暂显示“本机已保存”或失败原因 → 隐藏提示。
2. 手机：启动 FieldLog Companion → 用户主动点“测试定位” → 申请前台定位权限 → 获取位置及完整时间/精度信息 → 显示结果或明确失败原因。

Phase 1 不把照片与手机位置拼成记录，也不声称手机已经收到照片。眼镜在本阶段显示的是“本机已保存”，避免混淆为“已同步手机”。

手机定位优先使用可用的 Fused Location Provider；无法使用 Google Play services 时走 Android LocationManager。无 Google 服务设备与 Samsung 的结果分开验收，不预先宣称兼容。

## 计划中的项目内容

```text
RokidFieldLog/
  glasses-app/        Kotlin 眼镜应用、CameraX、私有照片和捕获元数据
  phone-app/          Kotlin 手机应用、两种定位提供者和诊断页面
  docs/              中文开发步骤、来源、验收与后续开源文档
  gradle/            Gradle Wrapper 与固定依赖版本
  scripts/           项目内环境启动、构建和只读诊断脚本
  .tools/            可选的项目专用 Android Studio / Android SDK
  .local/            本地 IDE 配置、缓存、临时文件和构建工具用户目录
```

上述目录已实施，并添加了 fieldlog-core 共享定位校验模块及项目专用测试。已配置 .gitignore 排除 .tools、.local、构建输出、私密数据和签名文件；Phase 4 再完成英文 README、MIT License 与完整开源说明。

眼镜首版使用轻量原生 Views，按绿色显示安全区域布局；CameraX 异步初始化，不显示实时预览。优先使用触控板点击，避开可能触发系统相机的镜腿按钮。权限只申请 CAMERA。

手机首版仅有定位诊断页面；分别处理精确/近似位置、拒绝权限、定位关闭、超时、无提供者及 Google 服务不可用。只请求 ACCESS_COARSE_LOCATION / ACCESS_FINE_LOCATION，不在 Phase 1 请求后台定位权限。页面会明确说明 Fused 结果可能融合 GPS、Wi-Fi 和移动网络，而不是承诺每次均为纯卫星 GPS。

## 按顺序运行的验收

必须先准备可用构建工具并通过两端 debug APK 构建。下载依赖、同步 Gradle或构建成功，均不能记作真机测试成功。

| 步骤 | 用户如何测试 | 预期结果 | 通过的证据 |
| --- | --- | --- | --- |
| 环境 | Android Studio 打开项目，Gradle Sync，依次构建两个模块。 | 两个 debug APK 可产生，没有依赖/Manifest/Kotlin 编译错误。 | 构建退出码与产物存在 |
| 眼镜连接 | 确认官方开发数据线及 Rokid AI App 的眼镜 ADB 开关；授权后运行针对指定设备的只读诊断。 | 指定眼镜处于可调试状态，系统版本与文档范围一致。 | 脱敏连接状态；不得提交序列号 |
| 眼镜启动 | 用户明确同意本次安装后，安装 glasses-app，打开 FieldLog。 | 显示可读绿色界面，触控事件正常。 | 用户观察与必要的脱敏日志 |
| 正常拍照 | 站定后点击一次拍照，等待提示。 | 私有目录出现可解码照片和 photoId/时间元数据；提示约 1.5 秒后隐藏。 | 在自己的 debug App 私有目录检查文件与解码结果 |
| 重启验证 | 关闭并重新打开 FieldLog。 | 上次照片仍存在；正式照片没有放在 cacheDir。 | 私有数据仍可读 |
| 摄像头失败 | 用户在权限提示中拒绝；或遇到实际相机占用错误。 | 明确提示原因，无崩溃、不报告成功；不得主动更改系统配置制造错误。 | 用户操作与真实错误结果 |
| 手机定位 | 用户同意安装 phone-app 后，在户外打开 App，授予定位权限并点击测试。 | 显示坐标、精度、位置时间、收到时间、数据年龄和定位来源。 | 真实定位结果，仅保存在私有目录 |
| 手机失败 | 用户拒绝权限，或在自身同意的情况下测试定位关闭/无信号。 | 显示拒绝、关闭或超时；坐标保持 null，没有伪造值。 | 真实失败状态 |
| 无 Google 服务 | 在实际无 GMS 手机测试系统定位路径，或先验证明确的提供者选择逻辑。 | 真机系统定位成功或解释实际失败原因；逻辑测试与真机结果分开记录。 | 单独的设备验收记录 |

连接电脑不等于允许安装软件。任何手机/眼镜安装、调试开关修改和数据删除都须得到对应授权；不自动安装官方 Demo，不执行 Root、刷机、系统重置、其他包卸载或设备数据清除。

## 阶段完成标准

- 两个应用均实际构建成功。
- 用户眼镜实际启动，至少保存并验证一张真实照片，且提示能自动隐藏。
- 至少一部实际 Android 手机成功获取位置，完整记录精度和位置时间。
- 权限拒绝和实际遇到的错误没有伪造成功；未覆盖设备/失败场景明确标记为待测。
- 更新文档：本次改动文件、可执行测试步骤、预期结果、构建证据、真机证据和未验证事项。

上述条件满足后，再进入 Phase 2。Phase 2 先核实真实 SDK 依赖和签名、建立小消息 ACK，再验证照片传输、时钟匹配、离线保存和完整记录。Phase 3 实施列表、地图修正、类别说明和用户选址导出；Phase 4 完成开源交付。
