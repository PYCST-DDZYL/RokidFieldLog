# 眼镜采集包到手机材料

1. 手机先在现场新建材料，填好地址和参照物并确认“对方能找到”；此时不需要照片。眼镜只采集同一处的环境照、细节照，等待保存和后台恢复结束。菜单第四项“导出采集包 / USB转存”（滑动选择、单指确认）生成同一FIELDLOG_CAPTURE_PACKAGE v1格式。
2. 确认导出未经打码的原图和采集JSON。成功后显示下载目录及全部文件名；超过100张或256 MiB自动拆成多个 `FieldLog_capture_<时间>_<批次>_001of2.zip` 等采集包，每包均可独立导入。256 MiB按解压后的照片、记录及清单合计计算。单张超过16 MiB、记录损坏或指纹变化时，在创建下载文件前停止，不静默漏图。
3. 用USB把屏幕列出的全部ZIP复制到电脑，再复制到手机下载目录。若眼镜不提供MTP，可在已经授权的电脑用ADB取出公开下载目录文件，无须run-as和debug版本。生成期间全部下载条目保持pending，全部写完再发布；失败时尝试清除本次所有条目，清理失败会明确提示检查下载目录，原照片始终保留。
4. 手机首页“导入采集包”逐个选择ZIP；每包导入后选择现场已确认地址的材料，再把这批照片加入对应材料。不要遗漏多包中的任何一包；重复导入同包不会重复新增记录。原地址和参照物保留，不另建空草稿。最多补到5张，超额看图选择，重复ID不重复加入；其他照片仍在图库。
5. 新增照片的角色待人工确认，重新核对同一问题/同次观察；逐张审阅隐私，无须遮挡时人工确认。补好真实接收方字段，再分段复制、分享JPG或保存交接ZIP。新材料默认通用人工交接，不强行套用江苏地区。

已授权电脑的PowerShell示例（占位符必须替换为实际设备号和眼镜屏幕上的确切文件名）：

```powershell
. .\scripts\Use-ProjectEnvironment.ps1
& "$env:ANDROID_HOME\platform-tools\adb.exe" -P 5047 -s <眼镜设备号> pull /sdcard/Download/FieldLog/<文件名>.zip .local/<文件名>.zip
& "$env:ANDROID_HOME\platform-tools\adb.exe" -P 5047 -s <手机设备号> push .local/<文件名>.zip /sdcard/Download/<文件名>.zip
```

采集ZIP包含原图及原始采集元数据，不是报修材料，不直接提交给官方渠道。公开下载文件和电脑/手机转存副本不会随“删除项目数据”被清除，需要用户自行管理。手机材料ZIP只含白名单字段和已审阅JPG；无线同步仍待Rokid协议与授权。

最近一次成功定位可在记录或材料里显式选用。界面展示坐标系、位置时间、精度和来源，并标注“拍摄者参考位置（非问题位置，非拍摄时定位）”；选用后会随材料交给接收方。后续定位失败或取消不会覆盖最近成功结果。原始坐标不会自动填入问题地址。现场“我在这里”仅在获得本次有效定位后向Android系统Geocoder请求文字建议，最多再等10秒；没有文字结果就手填，不把坐标伪装成地址。采用建议后仍要人工修改并确认，与照片拍摄时刻没有自动关联。

当前新增导出菜单的眼镜触控板、光学显示、MediaStore目录与实物USB转存仍需眼镜验收。JVM跨端格式回归只证明采集库写出的包能被手机库读取，不证明设备物理链路。
