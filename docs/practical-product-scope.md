# 实用性优先：首个报修场景

更新：2026-10-15。以下为产品假设和拟采用的验收标准，尚无现场效率、付费用户或当地成功受理结果。

## 要解决的问题

每天巡查的人需要在现场一次形成接收方能找到位置、看清问题、接手处理的材料，减少补拍、补地址和重复填写，并在处理后核对结果。第一批候选使用者是一个固定区域的物业、校园或园区巡检人员及其维修接收人；尚未确定试点，不能把他们写成已有客户。

先选择一个实际可接触的使用者和接收方，只验证步行道铺装破损报修。若实际只能接触个人街道上报，就选一个本地官方入口验证。是否需要眼镜，由完整工作耗时及佩戴接受度决定。

## 网上资料支持什么

- [宣城市住建局 2026-05-27 的官方教程](https://zjj.xuancheng.gov.cn/News/show/1712222.html)：至少两张不同角度的清晰照片，最好包含周围参照物；填写分类与描述，定位允许手动调整。它支持多视角和找现场的需求，不能证明本项目已经符合完整表单。
- [FixMyStreet 工作方式](https://fixmystreet.org/how-it-works/)：按位置和类别找到责任机构，展示已有报告与更新，减少重复上报。这些功能已有先例；本项目仍需要具体接收方与实际渠道验证。
- [英国四地住房维修调研，第 10–11 页](https://media.localdigital.gov.uk/uploads/2022/03/16113717/Final-Report-Housing-Repairs-Discovery-.pdf)：参与研究的伦敦地方政府中，约四成来电与已有维修事项有关。该特定业务研究提示后续沟通值得调查，不能据此推断国内园区有同样比例或愿意付费。
- [Bentley Blyncsy](https://www.bentley.com/products/blyncsy/) 已提供行车记录仪图像道路检测。AI 检测和持续观察均不能作为未经论证的首创声明；厂商性能与节省数字没有在本项目复现。

## 当前改动

增加独立的多图报修材料，与跨时间的问题历史分开：每份材料填写接收方、其问题分类、地址、附近参照物、人工确认的现场日期和说明；选 2–5 张照片，其中至少一张环境照和一张细节照。数量、角色、是否同一问题同一次观察由人核对，应用不识别照片语义。

每张照片分别完成隐私处理和实际 JPG 审阅；一次填写共用说明，无须重复填写每张记录的地址。已人工填写的照片日期如与材料日期冲突，先核对更正。演示与真实资料隔离，照片变更和保存期间的旧版本不能直接外传。位置采用明确文字地址及参照物，尚无地图点位修正。

导出为说明、白名单 JSON 和已审阅的 JPG，供解压后手动填写接收方渠道。2–5 张、每张最多 5 MB 是本版本的材料整理范围，不能泛化为全国政务限制。原有单图材料功能保留，但不视为多图渠道的完整材料。

## 用真实工作验收

先邀请 2–3 位真实使用者，用约 20 个真实事项做初步比较。使用自然发生的问题；合成演示仅用于练习，不能实际提交。试点负责人保管获准使用的资料，项目不默认上传照片或分享客户数据。

| 指标 | 记录方法 | 建议的初步继续条件 |
| --- | --- | --- |
| 材料首次可接手率 | 接收方不看原操作过程，凭材料找现场并说明要处理什么；逐条记录补拍、补地址、解释请求 | 目标至少 90%；是拟定门槛，不是已测结果 |
| 每条有效报修的总人工时间 | 计入采集、传输、整理、隐私处理、填写接收系统及返工；与现有手机/微信/表单流程比较 | 中位耗时目标下降至少 30%，同时报告样本量、范围及失败事项 |
| 保存与恢复 | 离线采集、打断保存、重开、重新导入，核查原始记录 | 不接受未说明的数据丢失；有限样本不能证明永不丢失 |
| 结果核对 | 记录实际受理、反馈与现场复查；遮挡或错位置单列 | 不把材料导出、人工回执或遮挡照片当作维修确认 |
| 眼镜的增量价值 | 同类任务交替使用手机和眼镜，计入设备准备、传输、失败返工、续航与佩戴负担 | 有明确收益再决定是否优先眼镜入口 |
| 持续使用 | 试用后让使用者选择继续当前方式或保留本工具，并问清原因 | 至少有真实使用者愿意继续，商业化另验证预算与付费决策人 |

当前没有完整耗时自动记录、在线协作、官方受理接口或真实用户试点结果。下一轮应取得接收方逐条反馈后再决定功能优先级。
