# 从零到一：投资判断与首个试点

这是针对本项目的产品判断和待验证假设，不代表 Peter Thiel 本人的意见，也不是已经取得的商业结果。

## 现在的判断

当前值得继续做工程和小规模试点，尚不足以凭现有证据作出投资决定。开源代码、CI 通过、眼镜能拍照是交付基础；没有证据证明使用者持续使用、接收方少返工、付费方愿意购买，或整个流程比手机加现有表单更省时。

Thiel 在[本人署名文章](https://www.wsj.com/articles/peter-thiel-competition-is-for-losers-1410535536)中区分创造价值与获取价值。对 FieldLog 的应用是：既要证明接收方获得更好的材料，也要找出谁能从中节省预算、并愿意为此支付。下面的目标和数字是本项目的建议，不是其原话或投资承诺。

## 七个投资前需要看到的因素

| 因素 | 本项目需要的证据 | 当前缺口与行动 |
| --- | --- | --- |
| 明确的小市场与付费方 | 一个固定园区、物业或校园里，谁每天步巡、谁接维修、谁掌握预算 | 先聚焦步行道铺装破损，找到同一使用团队和接收团队；这些目前只是候选角色，不是客户名单 |
| 有价值且不同的洞察 | 返工的主要原因究竟是漏发现、地址不清、照片不清，还是交接后无法确认修复 | 逐件记录额外要求、退回照片及复查结果；若主要问题与采集无关，及时调整产品方向 |
| 全流程明显改善 | 包括拍摄、USB 转存、定位、隐私审阅、填表、补拍和复查的总人工时间 | 和现有手机/微信/表单流程做同类任务对照；不能只展示一次快速拍照，也不能把省时假设写成“十倍”结果 |
| 持续使用与付费信号 | 非演示任务中重复使用，接收方愿意继续接收，预算负责人确认购买流程，最终有获准付费试点 | 点赞、安装量、GitHub 提交次数都不是付费证据；报价与合同由真实双方确定，不编造客户或价格 |
| 可积累的优势 | 同一地点跨次观察的历史、经过验证的交接流程、渠道模板、合法取得的评测资料 | MIT 代码本身容易复制。优势须经持续使用积累；照片和位置不默认汇总到云端，训练数据需另行取得使用权 |
| 稳定且能复制的交付 | 原图不丢失、版本可覆盖升级、异常可解释、已有数据能检查、正式接收流程可验收 | 本轮先修构建冲突和记录校验，增加本机健康检查；无线同步、地图、完整备份和真机矩阵仍未完成 |
| 单位经济与扩张路径 | 单个团队的部署/支持/硬件成本，以及负责人愿意支付的价值；第二个同类地点能否复用 | 先在同类地点复制。若眼镜加入后的总成本或耗时更高，就保留手机流程，不强行把硬件写成优势 |

## 产品切入与已有替代方案

候选切入点：让固定区域步巡员一次形成“能定位现场、能看清问题、能在处理后人工复查”的材料。用户是巡查员，接收人是实际维修团队，付费方候选是承担返工和管理成本的运营方。这仍需访谈及试点验证。

[FixMyStreet 的官方说明](https://fixmystreet.org/overview/)已经描述了把街道问题交给相应机构的开源平台；[Open311 GeoReport v2](https://wiki.open311.org/GeoReport_v2/)已有服务类型、问题创建及状态查询规范。因此不能把“照片加位置上报”称为新的独占市场。FieldLog 的假设优势放在步巡采集、一次交接完整度和跨次人工复查；尚无相对竞品或现有工作方式的性能证据。Open311 只是未来可研究的适配方向，本轮没有接入、没有新增在线提交。

## 拟议的首轮试验

- 范围：一个获准地点、同一种问题、2–3 位实际使用者，约 20 个自然发生的事项，建议观察两周。这是待执行计划，未安排现场活动或联系任何人。
- 对照：选复杂度相近的任务，轮换使用现有流程与 FieldLog。相同真实事项不能为测量而重复提交；练习用合成任务与真实接收结果分开。
- 完整计时：采集、转存、定位/地址、打码、填表、返工及复查均计入；现场负责人记录任务范围和起止点。只统计单次交接记录的耗时无法计算完整试点总成本。
- 材料首次可接手率：由实际接收人在不知道操作过程时判断，是否能找到现场并确定要处理什么。它与政府正式受理率不同，需要另外记录，不从“照片被接受”推断。
- 初步继续条件可预先约定为首次可接手率至少 90%、同类任务人工耗时中位数降低至少 50%、没有数据丢失或未经确认的维修关闭。这些是探索性目标；20 个事项不能证明普遍效果。
- 留存与成本：记录同一使用者第二周是否主动继续用、补拍和支持时间、硬件佩戴接受度；由负责人核对付费意愿及实际部署成本。当前没有自动收集使用者身份或行为。
- 停止或调整条件：定位/照片导致找错现场、丢失资料、接收方持续返工，或把 USB 和审核算入后不省时，应先解决原因；不能靠增加提交次数掩盖结果。

## 软件能记录什么

本轮接入的离线试点概览只汇总本机已有材料：明确的非演示标记、有试交日期的记录、人工填写回执、已填写分钟数和照片接收结果。空值继续作为未知，不填零；合成演示与损坏记录单独计数，不能抬高结果。同一问题的多份材料会计为多份；每份只有当前一份试交笔记，因此不能据此计算独立问题数、完整提交次数或全部返工成本。“非演示”是本机标记，不证明照片真实。

这些是本机人工登记，不能证明政府受理、工作人员身份、维修质量、人员留存、对照组耗时或付款。没有对照数据时不计算节省比例，没有接收人逐条判断时不计算首次可接手率。概览不含地址、联系人、原图或 GPS，不自动上传或发送；GitHub 只包含实现和合成测试。

## 本轮执行与后续门槛

先完成互斥构建、采集字段校验、本机资料健康检查与试点概览，分别回归和推送。源码进展可以自主完成；真实试点、目标单位接收要求、付费和现场验收需要现实证据，不能由代码或文档代替。下一步产品优先级由试点中最常见的失败原因决定。
