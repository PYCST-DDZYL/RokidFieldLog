# 离线记录整理预览

当前另有 [连续观察与维修复查](inspection-workflow.md)：将多次照片记录关联到一个稳定问题，接续维修反馈和独立人工复查。单张材料导出沿用本页流程。

手机端现在提供独立于眼镜连接的本地记录库。开发、JVM 合成图片验证和 APK 构建不需要连接手机。Android 界面的实际触控、旋转、文件选择器和 EXIF 方向仍需设备验收；电脑测试不替代这些结果。

## 使用流程

1. 打开 FieldLog Companion，选择“载入演示记录”，或通过系统文件选择器“导入采集包”。演示生成两张本地绘制图片，记录和导出材料均保留“合成演示”标记；没有现场拍照、GPS 或政府提交。
2. 在列表搜索地址、类别或说明，打开记录。独立选择问题类别，填写文字地址、确认地址、情况说明和事发日期，再保存。源记录和未知扩展字段保留在私有存储，编辑写入另一份版本化草稿。拍摄标签没有直接变成已核对类别，未知时间没有自动变成当天。
3. 坐标可留空；如手工填写，必须同时给出经纬度和 WGS84 / GCJ02 / BD09。原始拍摄者位置只供参考，不能当作问题位置。目前没有地图、逆地理编码或坐标转换。
4. 进入“查看照片 / 隐私遮挡”。画框覆盖人脸、车牌及其他无关信息；支持撤销框、清空、缩放、查看模式拖动。生成副本后显示实际 JPG，放大检查。没有遮挡框时必须明确确认不存在需要遮挡的第三方信息；每张照片均需确认可读性和遮挡完整。
5. 返回记录，选择“保存单图人工提交材料”，由系统文件选择器选择保存位置。生成时及真正写入前均校验地址、类别、说明、人工确认日期、实际文件指纹、JPEG、尺寸及隐私审阅绑定；选择位置期间若编辑或重新审阅照片，需要重新生成材料。保存成功只标记“材料已保存”。
6. 自行在官方渠道填写事项并上传审阅后的照片，获得回执后手动录入回执或处理结果。修改已导出或已提交事项的内容会回到“待整理”，历史回执仍保留。

通用材料包是一条记录一个 ZIP，包含 report.txt、summary.json、photo-reviewed.jpg。它不是官方接口请求，不承诺任何渠道直接接受 ZIP；用户从包内取出文本与 JPG 按当地表单填写。具体地区的字段、分类、附件限制核实后再实现渠道适配器。

## 采集包与材料包分开

导入使用私有的 FIELDLOG_CAPTURE_PACKAGE v1，详见 [数据格式](record-format.md#offline-capture-package)。它包含原图及源元数据，可能有 EXIF 和原始定位，只用于你自己的离线转移或备份，不适合提交或公开分享。眼镜无线传输和一键生成真实采集包尚未接入；现阶段可用内置演示或由核心 CapturePackage.write API 生成的包验证整理流程。

导入限 100 条、单图 16 MiB、单份 JSON 256 KiB、总解压数据 256 MiB；手机适配器限原图 2400 万像素。逐条检查路径、版本、编号、照片完整性、尺寸和已有 SHA-256；校验通过后整批提交。重复导入不覆盖草稿；编号冲突或坏包不提交任何新记录。损坏的现有草稿会保留并提示，不影响其他可读记录。忽略的 staging 子目录保留未完成事务时不会出现在记录库。

## 隐私副本

原图保留在 App 私有目录。副本先按照 EXIF 方向转正，再限制长边 2048 像素，用不透明黑色像素覆盖框选区域，重新编码 JPG；先用质量 93，必要时再压缩以满足 5,000,000 字节。导出副本不复制原图 EXIF、GPS、XMP、ICC、IPTC 或注释。照片检查针对最终输出文件，框不是仅用于屏幕显示的覆盖层。

导入时另外保存原图指纹；首次审阅前也检查原图仍与导入时相同。审阅绑定原图 SHA-256、输出 SHA-256、字节数、尺寸、框和渲染版本。导出重新计算双方指纹；字节变化阻止导出。归档清单使用字段白名单，不写源记录、原始手机定位、设备信息或回执。可选问题坐标仅来自手工确认，并保留明确坐标系。这里没有自动人脸/车牌检测，也无法自动判断人是否漏框；最终照片仍需用户检查。

## 数据与清理

记录在 files/fieldlog/offline/collections/<batch>/items/<photoId>/，包含 original.jpg、source.json、source-photo.sha256、draft.json 和 review-<uuid>.jpg。文件 I/O、解码、哈希、生成材料和删除均使用进程拥有的同一后台队列；列表只展示元数据。Activity 重建用草稿修订号防止旧页面覆盖新编辑。

返回调整遮挡、关闭审阅页时清理该页未采用的预览；新的审阅结果成功落盘后才清理原有已确认副本。延迟清理会重新核对当前审阅，保留已确认的照片和原图。取消材料保存、生成结果返回时页面已关闭或生成失败时清理本次临时材料。复制到用户位置途中失败时尝试删除不完整文件，具体取决于文档提供方是否允许。强制终止进程可能留下未引用私有文件，现阶段随记录或项目清理，不承诺启动时全面回收。

列表可清除演示记录，单条记录可确认删除。定位检查页的“删除全部项目数据”涵盖本 App 内 fieldlog 的全部照片、记录、定位检查及临时材料；不会删除已保存到用户自选位置的文件。原图和未采用的本机副本随该条记录一起删除。普通卸载清理私有文件，覆盖升级保留。

## 电脑验证

Linux/macOS：

~~~sh
./gradlew --no-daemon :fieldlog-core:test assembleDebug lintDebug -PfieldlogDemo=true
~~~

Windows 配置项目内工具后，可使用同样的 Gradle 任务：

~~~powershell
. ./scripts/Use-ProjectEnvironment.ps1
./gradlew.bat --no-daemon :fieldlog-core:test assembleDebug lintDebug -PfieldlogDemo=true
~~~

fieldlogDemo 只让合成图片工作流测试把样例写入被忽略的 .local/offline-preview：SYNTHETIC-capture-package.zip、SYNTHETIC-material.zip、report.txt、summary.json 和 photo-reviewed.jpg。所有内容明确为演示，不含真实拍摄或定位。测试直接检查 ZIP 条目、黑色遮挡区域、源数据未进入材料、重复/冲突/路径穿越/解压上限、文件改变后拒绝导出以及草稿修订与回执状态。

Android 侧还需按 [设备验证协议](field-validation.md) 验证四种旋转和四种镜像方向、远处小车牌、缩放画框边缘、进程重建、系统文件选择器取消/权限拒绝/磁盘满，以及导出后从文件管理器重新打开照片。没有模拟器或设备时不能把这些项记为通过。


## 同一问题的多张照片

首页新增“报修材料（环境照 + 细节照）”，可为一次现场观察统一填写接收方、分类、地址、参照物、日期和说明，并选入 2–5 张分别审阅的照片。原有单张记录与跨时间的问题历史继续独立；多图报修不会把维修前后自动混成一次观察。操作与限制见 [多图材料流程](multi-photo-materials.md)，真实价值按 [实用性验收](practical-product-scope.md) 评审。
