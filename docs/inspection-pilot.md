# 首个步行道路复查试点

## 要验证的产品假设

一个园区的设施管理方可能愿意为低成本、可核对的维修复查付费。已在园区步行的工作人员能否在原有工作中获得有效照片、减少重复整理，需要现场对照验证。当前软件与合成测试不能证明这一点，也不构成首创或市场独占证明。

## 第一批范围

由一个有维修管理权限、愿意提供反馈并参加评审的园区管理方参与。优先选择一条固定步行路线、20–50 个可明确指认的位置、两名参与人员，只评估步行道路表面破损及维修复查。先访谈三位可能的使用/付费决策者，确认当前流程、复查成本、采购条件及实际付费意愿。

照片仅围绕获准检查的设施获取。原始照片和客户资料由该试点管理，不默认跨客户共享。眼镜与手机均作为候选入口，暂不强制购买或依赖眼镜。

## 四周安排

| 阶段 | 工作 | 可审阅结果 |
| --- | --- | --- |
| 第 1 周 | 访谈、确定点位与同一问题判定规则，用现有手机拍照加表格跑基线 | 点位清单、流程耗时、问题与反馈定义 |
| 第 2 周 | 同一路线交替使用手机与眼镜记录；调换人员和先后顺序 | 有效照片率、记录中断次数、归档耗时 |
| 第 3 周 | 对自然发生的维修进行反馈和复查；加入明确标注的遮挡/无变化测试任务 | 同位置关联错误、证据不足、误判处理完成的逐条审阅 |
| 第 4 周 | 管理方盲评同批材料可用性，核算每条有效复查的全部人工耗时 | 是否节省时间、是否愿继续付费、未解决的问题 |

只使用实际发生或明确标注的测试维修，不为演示编造现场修复。若四周内真实维修样本不足，延长观察或缩小结论范围。

## 指标和继续条件

记录采集、整理、隐私处理、人工关联、复查审阅、返工各段耗时，使用外部秒表或统一记录表；当前 App 没有自动采集完整工作耗时。有效复查应满足同一地点、清晰可见、日期/先后可核对、结论有依据，并由管理方按照同一标准评审。

比较同一批任务中每条有效复查的总人工时间，同时记录设备费用、佩戴接受度、续航和失败返工。先报告相对基线的实际改善、样本量和失败返工，不预设十倍收益。首个多图报修场景按 [实用性验收](practical-product-scope.md) 的拟定门槛评审；复查任务单独核算，不能混用不同任务的耗时。小样本中没有错误不能推导出可靠性的普遍保证；错误关联和误判处理完成要逐例解释，不能用大量容易样本稀释。

试点结束至少回答：是否显著减少总工作量、是否减少重复整理、是否有管理方愿付费继续使用。若主要瓶颈仍是人工关联或额外走路成本，先改流程或验证视觉匹配的可行性。实测后决定优先使用哪种采集入口，以及是否值得扩大到第二个园区。
