# 政府合作前的项目检查

日期：2026-10-22。检查基于当前源码、本机合成回归和本机构建；不构成合作方验收或安全认证。现有产品范围是本地整理照片、人工交接材料及人工登记后续观察。合作单位和正式接收方式尚未提供，本轮沿用这一范围修复。

## 本次发现并修复的问题

以下均为测试可重现的代码问题。不是已经发生的泄漏、攻击或真实政务事故。

| 优先级 | 不足及影响 | 修复与验证 |
| --- | --- | --- |
| 高 | 问题历史直接交给 Gson 解析，字符串 `"true"` 可被当成同一地点或拍摄先后已确认；部分空值会沿用默认值。损坏记录可能被展示为已有人工结论。 | 解析历史前检查布尔、文字、整数及事件结构；错误记录计入不可读，不再追加保存或展示为已修复。回归核对原文件字节未变、正常历史仍可读取、关联照片继续受删除保护。 |
| 高 | JSON 重复字段被后值覆盖。一个记录同时写入“未确认”和“已确认”时，原有严格语法模式仍可能接受后者。 | 照片草稿、多图材料、采集记录、定位历史、采集包清单及问题历史共用重复字段检查；同时限制记录大小与嵌套深度。未知采集扩展仍按原有机制保留。 |
| 高 | JPEG 对外检查在首个扫描段开始处停止，忽略后续内容；只识别少数 APP 标记。未知 APP 段、扫描后的信息或嵌入缩略图可能通过检查。 | 用完整的新编码基线 JPEG 解析器检查到文件结尾，拒绝未检查的扫描及结尾数据；拒绝含私有 APP/注释的审阅副本。新编码清理只保留无缩略图的标准 JFIF APP0 头。回归检查正常像素及原文件不变、分享失败不留下新副本、不影响已分享快照。 |
| 中 | 多图材料和问题历史部分版本号、修订号及序号在反序列化前没有范围校验，超大整数可能截断为受支持的小整数。 | 解析前检查数值类型、整数写法及 Int/Long 范围；明确核对版本 1，拒绝数字字符串、小数、指数及溢出。 |
| 中 | 江苏入口的联系电话只检查允许字符，`-----`、`(   )` 等纯标点也能满足填写检查。 | 在原有长度和字符范围外要求至少 5 个数字。这只排除明显无效输入，不能证明号码真实、归属或符合具体渠道要求。 |
| 高 | 眼镜超过 100 张或 256 MiB 就无法导出，提示“分批转存”却没有对应操作；写入大小预算还遗漏清单字节，极限大小的包可能写得出但读不进。 | 导出自动按数量与字节拆包，写入与读取都计算清单；所有原图校验后才创建输出。全部包完成后才发布下载条目，失败尝试清理本次所有输出，清理不完整时明确提示。101 张真实编码的合成 JPEG 验证逐包手机导入与重复导入，稀疏合成字节夹具验证大小边界，另验证源文件损坏与第二包失败时保留原资料。 |

正常旧版草稿的默认值及已知格式继续支持。损坏的草稿、材料和问题历史保留原文件并阻止编辑、导出；眼镜采集恢复仍沿用先备份旧元数据、再尝试恢复照片记录的机制。此次修复不删除原图。旧审阅副本若不满足更严格的 JPEG 检查，需要用户重新生成并审阅；不会自动替用户确认。

| 完整备份与换机恢复缺失 | 系统备份已关闭。报修材料 ZIP 有意不包含私有原始记录、回执和完整问题历史；它不能用于恢复整个工作库。 | 确定保留期限和备份责任，实现并演练包括照片、草稿、回执和历史的受控完整备份/恢复；在此之前不得用卸载作为更新步骤。 |
| 记录来源与多人审计能力有限 | 文件指纹验证内容是否一致，手填日期、回执和维修结论由本机用户填写；当前没有工作人员身份、可信时间或跨设备审计。 | 与合作方确定是否仅作辅助材料；若需要多人权限或正式证据链，另行实现身份、操作留痕、时间和防篡改要求，并单独验收。 |

这些条件需要合作方、设备或新的明确产品需求，不能用本地测试通过代替。本轮没有向政府渠道提交事项、发送消息、安装应用、清除设备数据或操作其他应用。
