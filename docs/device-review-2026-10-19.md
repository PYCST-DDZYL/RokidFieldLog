# 手机实机检查与预览修复（2026-10-19）

本轮在 Samsung SM-S9480、Android 16 / API 36、有 Google Play services 的手机上执行。照片流程只用应用生成的两张合成演示图；没有拍摄或上传新的真实现场问题，没有修改原有现场草稿，没有向接收人发送消息。

## 实机发现与修复

### 构建期间编辑造成的旧内容

code 12 包内还有构建期间修改前的表单文字。直接检查 APK 的 DEX 字符串确认旧文案存在、最新文案缺失；编译文件时间晚于源文件时间，不能据此断定包一定包含最新内容。[先前记录](report-form-validation.md)已补充这一限制，不能沿用为当前源码一致性证明。

Windows 构建现在在开始和校验结束时对源码、资源、Gradle 配置和项目脚本计算内容指纹；输入变化时失败。`-Clean` 同时清理共享核心和两端，并关闭该次 Gradle 构建缓存。两端 APK 校验完成才在忽略目录写 `VERIFIED` 构建凭据；安装前检查该凭据、当前输入与 APK 哈希。构建中断、内容变化或包被替换时拒绝安装。凭据不包含个人位置或设备标识。

实际工具回归验证了输入不变、文档变化不影响指纹、修改/新增/移除源文件可被发现；没有凭据的旧包也已实际在设备操作前被安装脚本拒绝。重新构建后，实机找到了当前源码的新字段文案。

### 隐私照片预览失败

实机画框后点“生成导出照片预览”，原先显示 `Check failed.`，不能进入照片确认。修复后，两张图均生成 1280 × 960、界面显示约 24 KB 的实际副本。已目视检查：演示车牌文字被不透明黑块覆盖，裂缝与合成标记仍可见；两张均保存审阅并分配环境照、细节照角色，材料缺项检查通过。

修复先将预览绘制到明确的 sRGB 位图，编码后对本应用新生成的基线 JPEG 清理 APP1–APP15 与注释段，再执行原有元数据、指纹和解码检查。不会把原图直接删元数据后冒充审阅副本。临时编码文件与最终副本都在应用私有目录，正常结束清理本次编码临时文件；原图不变。

手机日志实际记录清除了 `e2` 段，与 [Skia 编码器参考实现按颜色空间附加 ICC 信息](https://skia.googlesource.com/skia.git/+/d2b9e48baf1697760afc1dc8ea3ad40110b8cacc/src/encode/SkJpegEncoderImpl.cpp)的行为一致。不能假定每个厂商实现完全相同，因此仍需其他手机验证。

该清理函数只接受本应用刚编码的单扫描基线 JPEG，不是任意原始 JPEG 的通用修复工具。渐进编码、异常长度、截断扫描、扫描后出现的额外标记或结束后的字节会拒绝；不会放宽导出的隐私校验来绕过错误。
