# 多图报修材料

手机首页选择“报修材料（环境照 + 细节照）”→“新建报修材料”。也可从单张照片记录进入“用这张照片新建多图报修材料”。草稿保存在本机私有目录，返回时保存；旋转会保留当前编辑。不同设备之间尚无材料同步。

1. 填实际接收人或渠道，按对方现有选项填写分类。已有四个照片标签不自动映射政务分类。
2. 填详细地址、附近参照物或设施编号，确认别人能找到现场。选择人工确认的本次现场日期，写清问题和处理请求。
3. 选择同一问题同一次现场的 2–5 张不同照片，指定至少一张环境照和一张细节照。照片列表可看缩略图、搜索、翻页；角色只是人工标记，不代表应用验证了画面内容。
4. 每张照片点“查看照片 / 隐私审阅”，查看原图、处理第三方信息并核对实际导出副本。共用地址和说明填一次即可。已登记日期冲突时可进入对应记录更正；不要将维修前后照片当作同一次观察。
5. 勾选同一问题、同一次观察及清晰可用的确认，点“保存草稿并检查缺项”。更改位置文字、照片选择、视角角色、日期或隐私副本后，需要相应重新核对。
6. 点“生成并保存报修材料”，选择系统提供的保存位置。应用重新核验照片和草稿版本，保存 ZIP。解压后把 report.txt 的说明和 photo-01.jpg 等图片填到对方现有渠道。summary.json 是本项目归档清单，ZIP 不是官方导入格式。导出不会提交事项或标记已维修。

每张处理后 JPG 最多 5,000,000 字节、长边最多 2048 像素；先检查问题细节是否清晰，再按接收方要求调整。2–5 张是本功能的产品范围，实际渠道可能要求不同张数、大小、分类、电话、定位或只允许现场拍摄；这些仍须当地核实。

选入材料的照片不能直接删除；先从材料中移除或删除材料草稿。删除草稿保留照片和问题历史。演示资料始终标记，不能混入真实材料。清除演示会同时清除其材料草稿，已保存到外部位置的文件仍由用户管理。

## 开发与验收

fieldlog-core 的 ReportDraft/ReportPhoto 定义一份现场材料；ReportCodec 限制版本、字段、数量、身份和长度。ReportRepository 共享既有后台队列与 AtomicTextFiles，修订号避免旧编辑覆盖；读取列表不批量解码原图。扫描同时识别 AtomicFile 的备份/临时伴随文件，历史无法读取时阻止可能失去关联的照片删除。

生成和最终写入外部位置之前均校验原图导入指纹、隐私副本指纹/尺寸/元数据、草稿和照片修订。对外只写共用报修文字和已审阅 JPG；不自动包含原始定位、设备字段、回执和跨时间的维修历史。指纹不能证明拍摄地点、时间或人的判断真实。

JVM 集成测试采用真实导入库和合成 JPEG，覆盖缺项、不同视角、逐张隐私、重复图片、已知日期冲突、改图、改临时 ZIP、旧版本、演示隔离、备份恢复和删除保护。-PfieldlogDemo=true 会生成忽略目录 .local/offline-preview/multi-photo-materials/SYNTHETIC-two-view-report.zip 及解压后的合成材料。它们不能当作真实报修提交。

Android 实际布局、系统返回、旋转、文件选择器和真机照片方向仍需设备验收。软件检查不能代替接收方实际接单；实际效率按 [实用性验收](practical-product-scope.md) 测量。
