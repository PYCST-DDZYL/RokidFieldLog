# Bug 检查与复测（2026-10-17）

本轮检查已有功能，没有添加识别模型、地图或无线通信。所有输入图片和位置夹具均为项目内合成测试，没有读取或修改手机相册、删除设备数据或修改系统设置。

## 修复的问题

| 问题 | 修复与边界 |
| --- | --- |
| 参考位置缺少经纬度时可能变成 `0,0` | 在 Gson 填默认值之前检查单照片和多照片草稿的原始 JSON。缺失、null、字符串坐标均拒绝；真正的数值 `0,0` 仍接受，整项未知仍保持 null |
| 坐标系与时间被默认或转换 | 参考位置必须明确带坐标系、来源、正整数 Long 时间戳；缺失坐标系、字符串、小数和溢出时间不再被默认为 WGS84 或截断。精度可以缺失或 null，但提供时必须是有效数值 |
| 新格式参考位置字段可能在旧版本保存时丢失 | 遇到未知字段停止读取/导出该记录，保留原文件；损坏文件及原图不被自动改写，其他可读记录继续列出 |
| 过期页面的移除标记覆盖参考位置 | `IssueActivity` 中“移除参考位置”和其他表单字段使用同一 revision 校验。此项经过代码审查，页面切换/旋转行为仍待真机复测 |
| 保存构建日志误判 SDK 警告为失败 | `Build.ps1` 使用已有原生命令包装器保留诊断并检查真实退出码。原脚本在 Windows PowerShell 5 重定向日志时实际出现过 `NativeCommandError` |

## 自行复测

在 Android Studio 的项目终端进入 `RokidFieldLog`，运行：

```powershell
.\scripts\Test-ToolEnvironment.ps1
.\scripts\Build.ps1 -Release -Verify -Clean *> .local/bugcheck-retest.log
Get-Content .local/bugcheck-retest.log -Tail 25
```

预期为 `BUILD SUCCESSFUL`、两次 `APK verified`、JUnit 193 项全通过，以及发布证书校验通过。发布构建需要原有 `.private` 密钥；不要生成新密钥来替换它。日志仅保存在忽略的 `.local` 中。

正常使用中，完整旧草稿应保持可读；未选择参考位置仍显示未选择，不能自动填零坐标。损坏记录应标为无法读取并保留数据，其他照片仍可查看。不要为复测去手工破坏设备上的真实记录；异常输入已由隔离夹具覆盖。

本轮未向设备安装或执行真机回归。既有一次真实手机 Fused 定位和地址建议的结果见[此前设备记录](material-flow-validation.md)，不扩大为所有机型定位、页面恢复、分享接收、USB 导出或眼镜触控已通过。识别准确率也不属于这些回归的验证范围。
